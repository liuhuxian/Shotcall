# 08 / 09 重构方案（草案）

> 状态：**草案 · 待实施**
> 本文只描述目标结构、字段与校验规则；不含代码改动、不含数据迁移。
> 依据作者与评审 Agent 的讨论定稿；与旧行为冲突处，以本文为准。

## 一、目标

把「创作」与「翻译」拆开：

```
08 镜头规划 = 把导演脑中的画面写成可执行的文字（含生成单元分组）
09 提示词   = 把已确认的镜头与单元忠实翻译成模型语言（受约束的编译）
```

核心原则：

> **08 确认完整拍法及可执行单元；09 忠实编译并检查实际输入；
> 文件确认不能代替素材与声音的语义验收。**

三条不变量：

1. **分组是拍法决策，归 08**。09 不得重新分组、改切点、改时长、改台词。
2. **帧数是模型规则，约束单元总帧数**，不约束单元内部的每个切点。
3. **无对白 ≠ 静音**。声音分四类声明，检查「是否引入未授权声音」，不搜英文关键词。

## 二、08：镜头规划

### 2.1 输入

```
05 正式剧本（已确认，按集）
07 图像资产（已确认，含当前绑定图）
06 压力测试（可选）
本场模型（已锁定，见第五节）
```

### 2.2 加载技能

```
film-cinedance 前三道门（档位 / 拍法与镜头 / 素材职责与质检）
performance-direction（表演节拍、视线、口型）
cinematography（构图、运镜）
lighting-direction（光位、光比、色温）
00-项目管理/LOCAL-FACTS.md（帧数、音色、能力字段）
```

### 2.3 产出：3 个文件，同一版本号，一次确认

```
08-镜头规划/<场次ID>/
  shot-plan-vNNN.md
  scene-space-map-vNNN.md
  reference-map-vNNN.md
```

三个文件**同名同版本、作为一组交付**：确认或退回都以整组为单位。
只换一张参考图也要重新出三份，这是为降低错配付出的代价，当前阶段接受。

### 2.4 shot-plan 结构

```markdown
# <场次ID> 镜头规划 · vNNN

## 一、本场要什么
（3–5 行：观感、节奏、取舍；角色声音与行为基线可集中写在这里）

## 二、镜头总表
| 镜号 | 叙事时长 | 景别/角度 | 机位与运动 | 对白 | 单元 |
|---|---|---|---|---|---|
| SH001 | 8.00s | 中全景 | 固定 | — | U001 |

## 三、逐镜
### SH001｜0.000–8.000
- 目的与调度：
- 动作与表演（含眼神、呼吸、停顿）：
- 构图与光线：
- 首帧硬状态：
- 尾帧硬状态：
- 对白（原文，谁说的）：
- 依据素材（reference-map 编号）：
- 连续性要求：必须单镜连续｜可拆
- 可合并对象：无｜与前镜（依据）

## 四、生成单元定义（09 唯一读取源）
### U001
- 内部镜号与切点：SH001（0–8.00）
- 提交时长 / 帧数：8.00s / 192 帧（H3：17n+5 合规）
- 单元首帧状态：
- 单元尾帧状态：
- 参考素材（按 <Picture n> 顺序）：
- 音色（按 <Audio n> 顺序）：
- 接续：无｜接 U000（方式：尾帧接首帧）

## 五、声音分层（每单元四类）
- 人物对白：谁 / 台词 / 估算时长
- 背景人声：无｜有（内容或「不可辨群声」）
- 环境音与音效：铃、椅、脚步……
- 配乐：无｜有（用途）

## 六、自检
- [ ] 单元覆盖全部镜头，不重不漏
- [ ] 单元时长合计 = 本场总时长
- [ ] 提交帧数符合本场模型规则
- [ ] 每个单元的首尾状态可独立描述
- [ ] 有绑定图但未采用的资产已写明理由
```

**总表只引用单元 ID；时长、帧数、素材、接续只写在「生成单元定义」一处**，避免两处手写。

### 2.5 分组规则

**默认**：1 镜 = 1 单元。

**合并**（多个镜头编入一个单元）需同时满足：

```
同空间 + 连续时间 + 素材与状态兼容 + 目标入口支持内部切镜
并且列出内部镜号与切点时间
```

H3 与 Seedance 2.5 均支持单元内部切镜；能力以 `LOCAL-FACTS.md` 的记录为准。

**拆分**（一个镜头分到多个单元）允许的理由：

```
超出模型单条上限
多人对话 / 复杂走位 / 素材冲突
已有失败证据（如口型、身份漂移）
```

**禁止**：

```
未经设计的截断（词句被砍断、动作接不上、切在运动峰值）
因「帧数到了」硬拆
```

**允许**：08 明确设计的画外对白跨切。

### 2.6 08 校验（登记前）

```
单元覆盖全部镜头，不重不漏
单元提交帧数符合本场模型规则
单元时长合计 = 总表叙事时长合计
每个单元有首尾状态
合并单元已列出内部镜号与切点
参考素材：来源 / 用途 / 授权依据齐全
```

## 三、09：提示词

### 3.1 输入

```
08 的 shot-plan / scene-space-map / reference-map（已确认，同一版本组）
07 图像资产（已确认）
本场模型（与 08 一致）
```

### 3.2 加载技能

```
minimax-h3-video-prompts（H3 六段式）
或 seedance 对应技能
```

### 3.3 产出

```
09-镜头与视频提示词/视频提示词/<场次ID>/
  minimax-h3-vNNN.md      或  seedance-2.5-vNNN.md
```

文件末尾附 `shotcall-units` 数据块（单元 id / 时长 / 镜号 / 参考图 / 音色 / chainFrom）。
每场每模型一个文件；多模型并存，互不覆盖。

### 3.4 硬规则

```
· 单元必须与 08 完全一致：数量、id、内部镜号、时长、帧数
· 单元内部切点必须写进正文（按时间轴），否则模型会演成长镜头
· 参考素材按 reference-map 的编号与顺序写 <Picture n> / <Audio n>
· 声音按 08 的四类声明表达；不得新增 08 未授权的声音
· chainFrom 默认 null；只有 08 明确要求接续时才填
· 正文按对应模型的官方结构
```

### 3.5 两类检查

**自动可查（登记前强制）**

```
单元数 / id / 内部镜号 / 时长 / 帧数与 08 一致
提交帧数符合本场模型规则
参考图文件存在，且与 reference-map 记录一致
有绑定图却被排除的资产，reference-map 已写理由
chainFrom 与 08 一致
```

**必须实读（语义检查，人工或 Agent 阅读后填写）**

```
素材里是谁、几个人、处于什么动作阶段
声音声明与画面是否矛盾（如嘴部静止却有人声）
素材职责是否被越界使用（场景图当首帧、身份图当构图）
```

> 系统只能做启发式提示（例如正文同时出现「嘴部静止」与「发声」描述），
> 不能声称自动完成语义验收。

## 五、模型管理

### 5.1 配置层级

```
项目默认：00-项目管理/project-status.md   modelId
场次覆盖：00-项目管理/工作台/models.json  {"N003": "seedance-2.5"}
单镜覆盖：不支持
```

解析函数：`scene_model(project, scene)` → 覆盖值优先，否则项目默认。

### 5.2 锁定

```
08 确认时锁定 modelId（写进确认记录）
换模型 = 本场 08 与 09 全部失效重做；其它场次不受影响
```

### 5.3 能力字段

`00-项目管理/LOCAL-FACTS.md` 按模型记录：

```
单元内部切镜：支持 / 不支持 / 未验证
单条上限：时长与帧数
合法帧数规则
参考素材数量上限
```

未验证的模型默认**禁止合并多镜**。
