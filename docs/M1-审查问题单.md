## 1 问题清单（按严重度）

### P0-01 真实成果确认仍必报 400：`scope` 是字符串，账本只收对象

- **文件:行**：`app/server.py:1660-1664`（`scope=body.get("scope") or {}`）、`app/approvals.py:323-326`（`if not isinstance(scope, dict): raise ValueError("scope 必须是对象")`）、`app/ui_src/template.html:1497`（`scope:art?art.scope:""`）
- **现象**：项目 `00-项目管理/artifact-state.json` 里 **32/32 条 `scope` 都是字符串**（`"全项目"`、`"N001"`、`"E001—E003／N001—N008"`…）；「待确认」页把 `art.scope` 原样 POST 给 `/api/artifact/confirm`；服务端未做类型转换，直接传给 `approvals.append`，后者只接受 dict → 400 `scope 必须是对象`。账本不写、旧缓存也不写，按钮 100% 失败。这不是“先写一半”，是**根本写不进去**。
- **复现（/tmp 临时项目，真实 Handler）**：
  - 请求体与 UI 一致：`{"path":"05-正式剧本/screenplay-timing-audit-v001.md","verdict":"pass","kind":"doc","scope":"全项目","stage":"05"}`
  - 结果：`400 {"error":"scope 必须是对象"}`；同样请求把 `scope` 换成 dict 才 `200`。
  - 模块级：`approvals.append(p,"file",rel,"pass",path=rel,scope="N001")` → `ValueError: scope 必须是对象`。
  - 真实数据核对：`artifacts.build(<正式项目>)` 的 13 个 draft 全部是非空字符串 scope（抽查 `05-正式剧本/…-v001.md` → `"E001—E003／N001—N008"`，`08-表演设计/N003-acting-v001.md` → `"N003"`）。
- **为什么测试没抓到**：AC-02 的 HTTP 用例固定传 `scope={"unit":"N001"}`（`app/test_m1_acceptance.py:436`），不是真实数据形状。测试绿，真实点一次就 400。
- **建议修法**：在 `/api/artifact/confirm` 落账前做类型归一：`str` → `{"label": s}`（保留原展示语义），`None/""` → `{}`；或让 `approvals.append` 接受字符串并包成 `{"text": s}`。再补一条**用真实形状（string scope）**的 AC-02 断言：200 + 账本一行 + 旧缓存合法 JSON。

### P1-01 `vjobs.resume` 重启重排时丢 `after`：接续任务不等上游、失败不连带取消

- **文件:行**：`app/vjobs.py:347-350`（resume 的 `tasks.append` 只有 `id/run/on_cancel`，**没有 `after`**）；对照正常提交 `app/vjobs.py:870-872` 是带 `after` 的。
- **现象**：重启后 `resume` 把 `queued` 任务重新 `sched.submit` 时没有把 `j["afterIds"]` 传给调度器；`sched._collect_ready` 看到 `after=[]` 就立即认为就绪。于是 A、B 同时派发；若 B 是接续镜，`_execute` 取 `afterIds[0]`（A）时 A 还没成片，只能退回 `latest_result` 找旧片或直接抛“接续失败”。同时“A 失败 → B cancelled”在重启后失效。
- **复现（/tmp 探针，mock `sched.submit` 捕获）**：
  - 任务库：`J-A`（`U001-A`，queued）、`J-B`（`U001-B`，queued，`afterIds=["J-A"]`，chain）
  - `vjobs.resume(proj)` 输出：`J-A after=None`，`J-B after=None`，而 `J-B` 的 `_jobs` 里 `afterIds=['J-A']` 仍在。
  - 即：任务记录知道依赖，调度项丢了依赖。
- **为什么测试没抓到**：`test_jobs_m1.py:304` 只测“依赖已失败 → 不重排”，没测“正常依赖重排后 `after` 是否保留”；AC-05 只走 `vjobs.submit`，不走到重启。
- **建议修法**：`tasks.append({"id": j["id"], "run": ..., "after": list(j.get("afterIds") or []), "on_cancel": ...})`；补一条 resume 成功路径断言：重排项 `after` 保留，且 A 失败（mock runner 抛错）→ B `cancelled/dependency_failed`。

### P1-02 `file` 审批的 `target` 与 `path` 可指向不同文件，门禁可被“张冠李戴”满足

- **文件:行**：`app/approvals.py:264-288`（`file_ok` 先按 `path` 匹配，再回退按 `target` 匹配）、`app/approvals.py:345-354`（`append` 的 `target` 与 `path` 各自独立，互不校验）、`app/server.py:1633-1638`（`/api/approval` 允许客户端分别传 `target` 和 `path`）。
- **现象**：`POST /api/approval {"kind":"file","target":"<提示词 A>","path":"<任意已存在文件 B>","verdict":"pass"}` 会成功；之后 `file_ok(A)` 返回这条记录，但记录的 `sha256` 是 B 的。于是：
  1. `/api/gen/submit` 的提示词文件门禁可以用“另一个文件”的 SHA 通过；
  2. 账本无法证明“当时批准的是 A 的内容”，审计链失真；
  3. 若未来有 Agent/脚本按 `target` 查询，会拿到错误的 SHA。
- **复现（/tmp）**：`relA="09-a/prompt-v009.md"`、`relB="02-b/bible.md"`；`append(p,"file",relA,"pass",path=relB)` 后 `file_ok(p,relA)` 返回记录，`sha256 == sha256(B)` 为 True。
- **补充**：`/api/artifact/confirm` 始终 `path=rel`、`target=rel`，所以正常 UI 路径不触发；但 `/api/approval` 是新增的公开写接口，且这是“门禁/审计”的核心不变量，不能靠调用方自觉。
- **建议修法**：`kind="file"` 时强制 `_normalize_rel(target) == path`（或让服务端忽略客户端 `target`，由 `path` 派生）；`file_ok` 在记录有 `path` 时只按 `path` 匹配，不再回退 `target`。补一条“target/path 不一致 → 400”的用例。

### P1-03 `_save` 快照与落盘顺序可倒置，旧快照会覆盖新状态

- **文件:行**：`app/vjobs.py:39-63`（`with _lock:` 只生成快照并释放，随后才开锁文件 `flock` + 写临时文件 + `os.replace`）。
- **现象/推理**：`os.replace` 确实保证“不会读到半截 JSON”，独立 `.lock` 文件也避开了 `replace` 换 inode 的问题（这两点没问题）。但**写盘顺序与快照顺序无关**：线程 T1 取旧快照 S1 后让出，T2 取新快照 S2 先拿到文件锁写入，T1 后写入 S1 → 磁盘上最后是新状态被旧状态覆盖。`_execute` 线程与 `_video_recovery_loop`（reconcile/sweep/recover，每 30s）会并发调用 `_save`，真实存在。
- **影响**：重启后可能把已经 `done` 的任务持久成 `running`/`aborted`；recover 可能重复认领，违背 M1 “重启不重复、可续跑”。
- **为什么测试没抓到**：`test_jobs_m1.py:280-300` 的 4×15 并发 `_save` 期间**状态完全不变**，所有快照相同，测不出倒序覆盖；它只证明了“无 `.tmp` 残留 / JSON 可读”。
- **建议修法**：把“取快照 + 写临时文件 + `os.replace`”放进同一把 `_lock`（写盘时间短，可接受），或给每次变更加单调 `revision`，写盘时拒绝比磁盘更旧的快照。补一个“线程 A 改 job1、线程 B 改 job2 后并发 `_save`，最终文件两个变更都在”的测试。

### P1-04 页头首屏仍显示 0 场 0 镜：`S` 覆盖发生在第一次 `render()` 之后且未再渲染

- **文件:行**：`app/build_ui.py:32-40`（`BOOT` 先 `await loadEp()`，再 fetch `/api/overview` 覆盖 `S`，但**没有再次 `render()`**）；`app/ui_src/template.html:3059-3060`（`bannerStat` 读 `S.scenes/S.shots/S.totalDur`）。
- **现象**：`loadEp()` 末尾会 `render()`（此时 `S` 还是旧模型 `D.stats`，即 0 场/0 镜/0 分）；随后 `S` 被覆盖，但页面不再重绘。下一次重绘要等 3 秒轮询 `pollProgOnce()` 第一次返回 changed。于是**首屏 0–3 秒仍是“0 场 · 0 镜 · 0.0 分”**，与 AC-01“首屏显示 8 场/6 镜”不符；`无分集数据` 文案已改掉，但数字仍是旧的。
- **为什么测试没抓到**：AC-01 的页面 DOM 断言被显式 SKIP（`app/test_m1_acceptance.py:333`），只验了 API。
- **建议修法**：`S` 覆盖后立即 `render()`；或把 `/api/overview` 的 fetch 放进 `loadEp()` 的首次 `render()` 之前。

### P1-05 镜头审批不绑 09 文件 SHA → 永不过期

- **文件:行**：`app/ui_src/template.html:1167-1176`（`approveShot` 只发 `kind/target/verdict/scope/notes`，**没有 `path`**）；`app/scenes.py:67-98`（`shot_details` 返回的镜头对象**没有 `source`**，前端也无从拿 shot-plan 路径）；`app/server.py:192-220`（`_generation_gate` 用 `state(...).stale` 判断）。
- **现象**：FR-B4 要求“记录 09 文件 SHA”；实际 shot 记录的 `path/sha256` 都是 null，`state(...,"shot",...)` 永远 `stale=False`。改了 `镜头规划/N00x/shot-plan*.md` 或镜头提示词后，镜头行仍显示“通过”，门禁仍放行（只有提示词文件自身的 `file` 审批会 stale，镜头表变化不会被发现）。
- **备注**：`approvals` 模块本身支持 shot+path+SHA（`test_approvals.py:308` 已证明），缺的是 UI/`shot_details` 这一环。
- **建议修法**：`shot_details` 带出 `source`（shot-plan 文件名）；`approveShot` 带上 `path`；或服务端在 `kind="shot"` 时自动绑定该场 shot-plan 文件并算 SHA。补一条“改 shot-plan → shot 审批 stale → 门禁阻断”的用例（AC-15/M2 也会用）。

### P1-06 `/api/gen/submit` 先入队后写批次，失败会留下“半条批次”

- **文件:行**：`app/server.py:1862-1885`（`vjobs.submit(...)` 之后才 `bdir.mkdir` + `write_text` + `approvals.append("batch", ...)`）。
- **现象**：一旦 `vjobs.submit` 成功，任务已进 `_jobs` 并交给调度器（可能已开始/排队生成）；此后 `generation-batches/<id>.json` 写入失败（磁盘满/权限）或 batch 审批追加失败，异常被统一 `except` 成 400。结果：**GPU 任务在跑，接口报失败，批次记录缺失或只有文件没有审批记录**，正是“不可追溯”。
- **附带缺口**：批次记录只有 `prompt/promptSha/params{steps,width,height,seed}`，缺 FR-B7 要求的 `refs[{path,sha256}]` 和 `recipe`（`lora/sigmas/sampler/attention` 等实际生成参数在 job 里有，但没进批次）。
- **建议修法**：先算好 batch id、写批次 JSON + 审批，成功后再 `vjobs.submit`；`submit` 失败则把批次标记 failed，不返回 200。批次里补 `refs`（path+sha256）与 `recipe`。补一条“写批次失败 → 不产生任务 / 任务被取消”的注入测试。

1. **AC-02 HTTP 用例的数据形状不真实（掩盖 P0-01）**：`app/test_m1_acceptance.py:436` 传 `scope={"unit":"N001"}`，而真实登记表 32/32 是字符串。建议至少加一条 string scope 用例。
