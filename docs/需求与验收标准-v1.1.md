## 2 目标与非目标

### 2.1 目标

1. 导演能在一个页面里看清 **00–09 每个阶段的成果、版本、确认状态、失效依赖**。
2. 导演能对 **场次、资产、镜头/提示词** 逐项审核；意见有锚点、有版本、可导出给 Agent。
3. 导演能对 **图片候选、视频候选** 做采用/备选/重做；采用不覆盖原文件。
4. 生成前必须同时满足 **文件级版本锁 + 镜头级确认**；未确认不允许提交。
5. 任务落盘、重启可续跑、依赖失败会连带取消、状态在 UI 与 DB 一致。
6. GPU 管理不再因采样本身抢卡；按卡启停仍用 `--cuda-device`。
7. 能看 **E001–E003** 的集/场索引与当前进度；135 集总览推迟到本期之后，不造假。
8. 能把 N001 已采用的 6 镜拼成可检查的成片（EDL/CSV + 可选 mp4），并标出缺口。

### 2.2 非目标

- 本期不做 135 集总览/内容生产；E004+ 留到下一期。
- 不修改 `05-正式剧本`、`02-角色圣经`、`08-表演设计` 等创作文件；`07-图像资产` 仅按 9B 新增采用/绑定快照，不改 `assets-v*.md` 正文。
- 不覆盖 `09-镜头与视频提示词` 下任何既有 vNNN；只新增版本/结果文件。
- 不做云端多租户、鉴权、账号体系；仍只监听 127.0.0.1。
- 不把“生成成功”等同于“采用”；不替导演做艺术判断。
- 不在验收中跑大规模生成；单次验证 ≤2 条/张，用完即撤或标 TEST。

## 3 核心数据模型

### 3.1 唯一事实源

| 数据 | 位置 | 读/写 | 说明 |
|---|---|---|---|
| 项目成果登记 | `00-项目管理/artifact-state.json` | **只读** | 项目自己的工具维护；工作台只读 + 核对 SHA |
| 审批账本 | `制作运行/approvals.jsonl` | 工作台追加写 | 文件/场/资产/镜/挑片/批次的唯一确认记录；不覆盖、不删除 |
| 生成批次 | `制作运行/generation-batches/<BATCH-ID>.json` | 工作台写一次 | 绑定 approvals、prompt SHA、参考图 SHA、参数、单元、范围 |
| 任务库 | M1：`制作运行/jobs.jsonl` + 文件锁；M2 起迁 `制作运行/jobs.db`（SQLite WAL） | 工作台单写者 | 视频/图片任务、依赖、事件；重启可恢复 |
| 图片采用 | `制作运行/图片采用.jsonl` + `07-图像资产/资产绑定/asset-bindings-*.md` 新快照 | 工作台追加写 | 采用写新绑定快照（Q9=B）；不改 `assets-v*.md` 与既有快照 |
| 挑片 | `制作运行/selections.jsonl` | 工作台追加写 | 一镜一个 adopt；备选/重做保留历史 |
| 本地确认缓存 | `制作运行/确认状态.json` | M1 兼容读，M2 起只读迁移 | 不再双写；以 approvals 为准 |
| 旧决策 | `制作运行/decisions.jsonl` | 只读归档 | 旧 gate 1/2/3；新流程不再写 |

### 3.2 审批记录（approvals.jsonl）

```json
{"id":"APR-20261124-0001","kind":"file","target":"09-.../视频提示词/N001/minimax-h3-ref2va-v009.md",
 "path":"09-.../minimax-h3-ref2va-v009.md","sha256":"…","version":"v009",
 "verdict":"pass","scope":{"unit":"N001"},"notes":[{"anchor":"U001-A","text":"…"}],
 "supersedes":null,"by":"director","at":"2026-11-24T13:20:00+08:00"}
```

- `kind`：`file | scene | asset | shot | pick | batch`。
- `verdict`：`pass | revise | hold | na`。
- 同一 `kind+target` 的新记录带 `supersedes`；旧记录保留。
- 文件类记录的 `sha256` 必须等于当前文件 SHA；不等即 `stale`。
- 场/镜/资产记录的 `target` 用稳定 ID：`scene:N001`、`shot:N001/SH001`、`asset:C01-A`。

### 3.3 任务状态机

```
queued → ready → dispatched → running → succeeded
   ↘        ↘         ↘          ↘
   cancelled  cancelled  failed   failed
   （依赖失败 / 手动 / 超时 / ComfyUI 报错）
```

- 只有 `succeeded` 才解锁下游；`failed/aborted/cancelled` 都必须**连带取消**依赖它的任务，并写事件。
- `waiting` 不再是独立状态：ComfyUI 内排队 = `dispatched` + `queueState=waiting`；UI 显示“排队”，不显示“生成中”。
- 每个任务有 `depends_on`（JSON 数组）；调度器只从 `ready` 取任务。
- 所有状态迁移只经过 `app/jobstore.py` 一个函数；M1 用 JSONL 原子写 + `fcntl` 文件锁，M2 迁 SQLite；Web/worker 不直接改存储。
- 任务记录必须含：`id, kind, scene, unit, shots, prompt_sha, approval_ids, params, refs[{path,sha256}], created_at, state, events[]`。

### 3.4 场/镜/单元关系

- 场：`N001`–`N008`（当前 05 锁定表 8 场；04 大纲 261 场）。
- 镜：`SH001`–`SH006`（当前只有 N001 有 `shot-plan-v001.md`）。
- 生成单元：`U001-A`（SH001）、`U001-B`（SH002）、v005 的 `U001`（SH001+SH002）等。
- **门禁规则**：一个生成单元覆盖的**所有镜头**都有有效 `shot` 审批，且其提示词文件有有效 `file` 审批，才允许提交；缺一即阻断并列出缺哪一项。

## 4 功能需求

### A. 00–09 台账与当前批次索引

- **FR-A1** 阶段看板：10 个阶段、成果数、草稿/确认/替代/结论、文件缺失/改动/失效依赖；点击查看成果明细。
- **FR-A2** 成果详情：路径、kind、scope、SHA、大小、依赖、本地确认状态；Markdown/文本/图片/视频查看。
- **FR-A3** 未登记扫描：列出比登记表更新的 vNNN 文档；可本地确认，但**不修改 artifact-state.json**。
- **FR-A4** 当前批次索引（本期）：从 05 锁定表 + 04 的 E001–E003 行解析 3 集 / 8 场（标题、场号、时长、钩子）；**135 集索引推迟到下一期**，本期不解析 135 集表、不显示假 E004+。
- **FR-A5** 集详情：E001–E003 显示真实 05/08/09 进度；无 05/08/09 的集只显示“尚无剧本/分镜”，不造内容。
- **FR-A6** 集进度：E001–E003 显示 剧本/表演/分镜/提示词/候选/采用/成片 的状态点；无数据用“—”，不显示假 0。

### B. 确认与授权（核心门禁）

- **FR-B1** 文件级确认：对任意登录成果做 pass/revise/hold；记录 path + sha256 + version；文件改动后自动 stale。
- **FR-B2** 场级确认：对 `Nxxx` 的 05 剧本 + 08 表演做审核；意见锚定到台词/段落；pass/revise/hold。
- **FR-B3** 资产级确认：对 07 资产项（C/L/P/辅助）做审核；通过/需修改/忽略；审核本身不改 07；图片采用按 FR-E5 新增快照。
- **FR-B4** 镜级确认：对 `Nxxx/SHxxx` 的 09 镜头表 + 提示词做审核；通过/需修改/待定；记录 09 文件 SHA。
- **FR-B5** 文件版本锁：09 提示词版本（vNNN）必须被文件级确认；当前锁定版本参与 generation；未确认/已 stale 一律阻断。
- **FR-B6** 镜头门禁：生成单元覆盖的每个镜头都必须有有效 shot 审批；提交前返回缺失清单。
- **FR-B7** 批次记录：每次提交写 `generation-batches/<id>.json`，含 approvals、prompt_sha、refs（path+sha256）、params（steps/size/seed/recipe）、units、scope、at；不可覆盖。
- **FR-B8** 撤回/改判：新审批带 `supersedes`；不删除历史；UI 显示“当前有效/已被替代”。
- **FR-B9** 无旁路：删除 `force`；任何“强制提交”都必须是一条显式审批记录（`kind=file` + `verdict=pass` + note），否则 400。

### C. 四段审核（在 00–09 上重建）

- **FR-C1** 审核一 · 剧本/表演：场次列表 + 05 正文 + 08 表演要点 + 资产引用 + 原著出处；逐场判定。
- **FR-C2** 审核二 · 资产：角色/场景/道具/辅助分组；绑定图、版本、已忽略；逐项判定。
- **FR-C3** 审核三 · 分镜/提示词：镜头表 + 首帧/尾帧 + 参考图 + 六段式提示词 + 版本；逐镜判定。
- **FR-C4** 审核四 · 挑片：候选视频/图片；采用/备选/重做 + 原因；逐镜/逐单元。
- **FR-C5** 意见导出：一键导出当前所有审批 + 意见 + 版本清单（Markdown/JSON），给 Agent 改稿。
- **FR-C6** 失效传播：05 某场变化 → 该场 scene 审批 stale → 该场 shots 审批 stale；07 资产变化 → asset 审批 stale；09 某镜提示词变化 → shot 审批 stale + 相关候选标“旧版”。

### D. 视频生成与任务

- **FR-D1** 生成台：场次/单元/版本/锁定状态/确认状态/参考图/已有结果；勾选单元、次数、接上镜、分辨率、步数、种子。
- **FR-D2** 提交前预检：文件审批、镜头审批、参考图存在、帧数 124–362（或显式标“超界需裁”）、宽高 32 倍数、提示词非空；任一失败阻断并列出。
- **FR-D3** 提交：写批次记录 + 任务入库；返回 batch/job IDs；不阻塞 UI。
- **FR-D4** 任务状态：生成台/算力页显示 queued/ready/dispatched(排队)/running/succeeded/failed/cancelled；ETA 按本机实测速率。
- **FR-D5** 依赖串行：B 依赖 A；A succeeded 才 ready；A failed 则 B cancelled 并写事件；跨批依赖只认本批。
- **FR-D6** 重启恢复：queued/ready 重新入队；dispatched/running 按 prompt_id + 提示词全文 reconcile；已完成的按 history/recover 收片；不重复提交。
- **FR-D7** 取消/中断/删除：排队任务可取消；running 可中断；结果删除只删 09 生成结果下的 mp4，并保留历史记录。
- **FR-D8** 首帧接续：只对显式 `chain=true` 的任务生成 first_frame；记录来源单元/文件/SHA；来源更新后结果标“源已过期”；`chain=false` 不得标接续。
- **FR-D9** 重试：网络/ComfyUI 5xx 可重试 ≤2；内容失败不自动重抽；连续失败 3 次停止本批。
