# 导演工作台 · 工作流程说明

> 生成时间：2026-11-27 00:32　·　数据来源：工作台流程定义 `app/flow.py`

> 本文只说明**流程本身**：有哪些阶段、每步用什么技能、产出什么文件、谁依赖谁。
> 流程卡只负责给输入；产物清单、命名与验收标准由对应 skill 决定。
> 它不记录任何具体项目的进度、状态或版本，也不参与依赖判定与校验。

## 〇、卡片与技能的分工

流程卡里写的是**只有这个项目知道的事**：项目根、场次、要读哪些上游文件、边界（只做本阶段、不自行确认、不调生成接口）。
至于“这一步产出哪些文件、怎么命名、版本怎么递增、验收看什么”，全部以对应 skill 为准，卡片不复述。
这样技能更新时流程自动跟上，不会出现卡片和技能各说一套。

## 〇·二、技能分层与版本

技能分两层，职责不重叠：

| 层 | 位置 | 管什么 | 会不会随上游变 |
|---|---|---|---|
| 流程层 | 项目内 `.agents/skills/`（如 `film-cinedance`） | 档位、门禁、依赖链、生成单元、时长预算、交付契约 | 由本项目维护 |
| craft 层 | 项目内 `.agents/skills-upstream/` | 构图、运镜、光线、表演、H3 写法 | 固定上游 commit，手动升级 |

流程层决定「交付什么、合不合规」，craft 层决定「写得好不好」；craft 层不产出文件。

### craft 技能从哪来

| 技能 | 上游仓库 | 固定 commit |
|---|---|---|
| `cinematography` | fal-ai-community/skills | `653a2b7955a8` |
| `lighting-direction` | calesthio/generative-media-skills | `d5daa8a23514` |
| `performance-direction` | calesthio/generative-media-skills | `d5daa8a23514` |
| `minimax-h3-prompt-writing` | MiniMax-AI/MiniMax-H3 | `b731d8846cf7` |

指针与校验放在工作台仓库 `skills-deps/`：`meta/skills.map.json` 记录仓库+commit+文件 sha1，
`vendor/` 是三个上游仓库的 submodule，`scripts/verify.sh` 逐字节比对项目内副本。

### 项目实测约束放哪

上游技能不知道本机的帧数规则、数据块契约和音色挂法，这些写在项目自己的
`00-项目管理/LOCAL-FACTS.md`，与上游同步互不覆盖。尚未验证的现象不写进规则，只列在「待观察」。

### 升级方式

```text
改 skills.map.json 的 commit → 更新 submodule 指针 → verify.sh 校验
  → 同步项目副本 → 跑一条测试片确认没退化 → 提交
```

不跟随上游 main：技能一改，出片行为就变。

## 二、每步产出什么文件

| 阶段 | 产出路径（`{v}` 为三位版本号） | 这个文件是什么 | 上游 |
|---|---|---|---|
| 01 | `01-概念锚定/synopsis-{v}.md` | 故事核心：主题、类型、基调、篇幅、核心冲突与结局方向 | — |
| 02 | `02-角色圣经/characters-{v}.md` | 人物身份、外形、年龄、关系、说话方式与人物弧线 | 01 |
| 03 | `03-世界观/worldbuilding-{v}.md` | 时代、地域、制度、行业与生活口径（可跳过） | 01、02 |
| 04 | `04-分场大纲/treatment-{v}.md` | 分场表：场号、地点、时间、事件顺序与时长预算 | 01、02、03 |
| 05 | `05-正式剧本/{episode}/screenplay-{v}.md` | 可拍摄剧本：场次、动作、对白；事件与台词的唯一权威 | 04、02、03 |
| 05 | `05-正式剧本/{episode}/screenplay-timing-audit-{v}.md`（时长复核） | 逐场时长核算，与 04 预算对照，判断本批是否超时 | 同上 |
| 05 | `05-正式剧本/{episode}/novel-adaptation-audit-{v}.md`（小说对账） | 原著章节锚点与剧本改动逐段对照：保留了什么、为什么改 | 同上 |
| 05 | `05-正式剧本/{episode}/production-breakdown-{v}.md`（生产拆解） | 逐场制片信息：角色服装、空间道具、声音、动作风险与时长索引 | 同上 |
| 06 | `06-剧本压力测试/{episode}/stress-test-report-{v}.md` | 结构、节奏、逻辑与人物动机的压力测试结论 | 05 |
| 07 | `07-图像资产/assets-{v}.md` | 角色/场景/道具的资产清单、图片提示词与连续性交接 | 05 |
| 08 | `08-镜头规划/{scene}/shot-plan-{v}.md` | 镜头表：逐镜动作、表演、构图、光线、首尾状态、对白与生成单元定义 | 05、07 |
| 08 | `08-镜头规划/{scene}/scene-space-map-{v}.md`（空间图） | 空间坐标、轴线、光向与摄影机一侧 | 同上 |
| 08 | `08-镜头规划/{scene}/reference-map-{v}.md`（参考图映射） | 哪一镜用哪张图、每张图只负责什么 | 同上 |
| 09 | `09-镜头与视频提示词/视频提示词/{scene}/minimax-h3-{v}.md` | 模型提示词：按规划编译，末尾附 shotcall-units 数据块 | 08、07 |

> 产出路径按文件性质归档，不代表由该阶段的卡片生成。
> 05 与 06 按集管理：路径里的 `{episode}` 是集号（E001），一集一组文件；切集时 05/06 卡片随之切换。

## 三、依赖规则

```text
00 原始资料（小说/原稿，外部提供）
  ↓
01 概念锚定 → 02 角色圣经 → 03 世界观（可选）→ 04 分场大纲
  ↓
05 正式剧本 ──┬→ 05b 时长复核
              ├→ 06 压力测试（可选）
              ├→ 07 图像资产（含音色参考）
              └→ 08 镜头规划（逐场，含生成单元）
                       ↓
                  09 视频提示词（按已确认的单元编译）
                       ↓
                  生成台 → ComfyUI → 成片
```

三条硬规则（由项目校验脚本执行）：

1. **生成单元**必须直接依赖同场镜头清单。
2. **视频提示词**必须依赖同场、同模型的生成单元；ref2va 类允许直接依赖镜头表。
3. **镜头表、导演方案、时长表**必须有已登记的权威剧本或作者原稿作为依据。

## 四、版本与登记

- 每次改动都**新增版本**（`-v001`、`-v002`…），不覆盖旧版。
- 一个文件被登记后才有 sha256；文件内容一变，哈希就对不上，系统会标它“已改动”。
- 上游文件被替换或改动，下游会标“依赖失效”，需要重新确认。
- 同一族文件（同一个文件名前缀）在同一时间只应有一个「当前版」。

## 五、确认与生成门禁

| 环节 | 谁把关 | 结果 |
|---|---|---|
| 文件确认 | 导演在工作台点「确认」 | 写入审批账本，绑定文件 sha |
| 提交生成 | 生成台检查提示词是否已确认 | 未确认或 sha 已变 → 拒绝提交 |
| 出片入库 | 任务完成后落到成片目录 | 记录耗时、排队、工作流、参考图 |

## 七、如何更新本文

```bash
cd ~/gen_v/Shotcall
python3 app/docgen_workflow.py -o docs/workflow.md   # 重生成本文
./skills-deps/scripts/verify.sh                   # 校验技能副本与上游一致
```

流程卡（阶段、技能、产出路径、上游依赖）改了就重跑一次；
它只读 `app/flow.py`，不读任何项目数据。
