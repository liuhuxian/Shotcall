# 导演工作台 · 工作流程说明

> 生成时间：2026-11-25 12:58　·　数据来源：工作台流程定义 `app/flow.py`

> 本文只说明**流程本身**：有哪些阶段、每步用什么技能、产出什么文件、谁依赖谁。
> 流程卡只负责给输入；产物清单、命名与验收标准由对应 skill 决定。
> 它不记录任何具体项目的进度、状态或版本，也不参与依赖判定与校验。

## 〇、卡片与技能的分工

流程卡里写的是**只有这个项目知道的事**：项目根、场次、要读哪些上游文件、边界（只做本阶段、不自行确认、不调生成接口）。
至于“这一步产出哪些文件、怎么命名、版本怎么递增、验收看什么”，全部以对应 skill 为准，卡片不复述。
这样技能更新时流程自动跟上，不会出现卡片和技能各说一套。

### 09 镜头规划下的配套文件

这些文件由 `film-cinedance` 技能定义（“拍法、镜头与生成单元确认门”三个内部门禁），
流程卡不逐一列举，只保证它们能进入登记与确认流程。

| 文件 | 作用 |
|---|---|
| `09-…/镜头规划/<场次>/scene-registry.md` | 场次登记（每场一份，不升版本） |
| `09-…/镜头规划/<场次>/scene-timing-vNNN.md` | 逐镜时长表 |
| `09-…/镜头规划/<场次>/scene-space-map-vNNN.md` | 空间关系与走位 |
| `09-…/镜头规划/<场次>/director-plan-vNNN.md` | 导演意图与取舍 |
| `09-…/镜头规划/<场次>/reference-map-vNNN.md` | 哪张参考图对应哪一镜 |
| `09-…/镜头规划/<场次>/continuity-ledger-vNNN.md` | 连续性台账：服装、光向、持物 |
| `09-…/镜头规划/<场次>/visual-continuity-audit-vNNN.md` | 视觉连贯自查 |
| `09-…/镜头规划/<场次>/generation-units-minimax-h3-vNNN.md` | 生成单元规划：哪几镜合成一次生成 |

## 三、依赖规则

```text
00 原始资料（小说/原稿，外部提供）
  ↓
01 概念锚定 → 02 角色圣经 → 03 世界观（可选）→ 04 分场大纲
  ↓
05 正式剧本 ──┬→ 05b 时长复核
              ├→ 06 压力测试（可选）
              ├→ 07 图像资产（含音色参考）
              └→ 08 表演设计（逐场）
                       ↓
                  09 镜头规划（含生成单元规划）→ 视频提示词
                       ↓
                  生成台 → ComfyUI → 成片
```

三条硬规则（由项目校验脚本执行）：

1. **生成单元**必须直接依赖同场镜头清单。
2. **视频提示词**必须依赖同场、同模型的生成单元；ref2va 类允许直接依赖镜头表。
3. **镜头表、导演方案、时长表**必须有已登记的权威剧本或作者原稿作为依据。

## 四、版本与登记

- 每次改动都**新增版本**（`-v001`、`-v002`…），不覆盖旧版。
- 一个文件被登记后才有 sha256；文件内容一变，哈希就对不上，系统会标它“已改动”。
- 上游文件被替换或改动，下游会标“依赖失效”，需要重新确认。
- 同一族文件（同一个文件名前缀）在同一时间只应有一个「当前版」。

## 五、确认与生成门禁

| 环节 | 谁把关 | 结果 |
|---|---|---|
| 文件确认 | 导演在工作台点「确认」 | 写入审批账本，绑定文件 sha |
| 提交生成 | 生成台检查提示词是否已确认 | 未确认或 sha 已变 → 拒绝提交 |
| 出片入库 | 任务完成后落到成片目录 | 记录耗时、排队、工作流、参考图 |

## 七、如何更新本文

```bash
cd ~/gen_v/Shotcall
python3 app/docgen_workflow.py -o docs/workflow.md
```

流程卡（阶段、技能、产出路径、上游依赖）改了就重跑一次；
它只读 `app/flow.py`，不读任何项目数据。
